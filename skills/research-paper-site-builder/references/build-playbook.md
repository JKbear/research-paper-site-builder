# 从两项输入到可运行的网站

本手册是交给执行建站代理的施工约定。下列命令是**目标项目应实现的接口**，不是 Skill 自带的采集程序，也不表示当前目录已经有这些脚本。现有项目可映射到等价命令。

## 阶段 1：把用户的自然语言落实为范围

1. 接收期刊清单与研究兴趣，保留原话，生成 `site.config.json`。只填已知事实；ISSN、官网和 feed 不确定时留 pending。
2. 将领域拆为中英文同义词、主题、歧义词和排除词。用户列出的独立兴趣必须保留在正向范围规则，不能只放进主题而被入口筛选漏掉；若将多个兴趣解释为交集，说明这一实质收窄并取得必要澄清。不要把“机器学习”这样的通用方法词单独当作目标领域相关性证据。
3. `includeAny` 任一词命中即可形成范围建议；或 `includeAllGroups` 的每组至少命中一词。两者为 OR。空组集合不构成真值；两种规则都空是配置错误。主题命中仅分组，不能替代范围判断。
4. 英文采用大小写无关、单词边界与短语归一化，中文按词组匹配；不要把 fault 匹配成 fault-tolerant 就自动归入断层领域。排除词与正向范围同时命中时进入歧义待核，保留命中原因，避免机械否决交叉学科论文。
5. `mode=targeted` 的综合刊按领域筛选；`mode=all` 只在用户明确需要全刊追踪时使用。全刊模式仍执行论文类型、DOI、证据与出版状态检查。
6. 制作少量正例、领域外反例、交叉学科边界例，运行范围规则，展示结果。不要仅用全是正例的样本证明规则有效。

## 阶段 2：逐刊核查入口

建立 `docs/sources.md`，逐刊记录：输入名称、官网、印刷/电子 ISSN、入口类型与URL、实际请求时间、状态码、响应类型、样例 DOI、题名核对、已知缺项、启用状态。

按可用性选择：官网 RSS/Atom → 官网开放目录/数据接口 → 按已核实 ISSN 查询 Crossref。每次选择都保留事实依据，不声称后者是官网 RSS。不要猜测出版方 URL 模板。仅在必要时打开浏览器核查动态来源；已有专用工具优先。

实际请求至少核对：

- 200 响应是否真是 RSS/XML/JSON，而不是访问挑战 HTML。
- 条目是否属于该期刊、是否包含原题/DOI或可信原文链接。
- DOI 在原文页或 Crossref 中是否对应同一题名与期刊；用标题补 DOI 时要求规范化后精确匹配并限定期刊，模糊匹配只产待审建议。
- 年刊、低频刊采用适合出版周期的回溯；综合刊有分页及数量截断检查，固定取前12条不能代表全面覆盖。
- 本地与 GitHub 云端各实跑一次，注明差异。403/429/挑战页面记录来源失败并采用已验证替代，不能用绕过访问控制或隐藏失败的方式接通。

## 阶段 3：实现最小可靠的数据管线

推荐轻量结构，可按现有技术栈调整：

```text
site.config.json
package.json
server.mjs                    # 仅监听 127.0.0.1 的预览/本地审核
lib/config.mjs                # 全链路共用配置
lib/sources/                  # rss、官方接口、crossref 适配
lib/catalog.mjs               # 归一化、去重、公开数据投影
lib/scope.mjs                 # 配置驱动领域判断
lib/editorial.mjs             # 人工决定与历史
scripts/collect.mjs
scripts/review.mjs
scripts/build-static.mjs
scripts/check-release.mjs
scripts/check-production.mjs
data/journals.json             # 可由配置派生，不能出现两个独立真源
data/discovered.json
data/editorial-reviews.json
data/source-health.json
data/collection-runs.jsonl
public/
tests/
work/                         # 运行证据、备份与隔离构建；不入 Git
```

目标命令契约：

| 命令 | 必须产生的行为 |
|---|---|
| `npm start` | 启动本地站并输出实际地址；默认不暴露网络写接口 |
| `npm run collect -- --journal ID` | 指定来源试采，输出真实成功/失败和新增数 |
| `npm run collect` | 全量采集、逐刊健康、追加日志、幂等合并，不部署 |
| `npm run review -- ...` | 默认预览决定；明确 apply 才保存人工决定与历史 |
| `npm run build:static` | 输出独立预览目录、公开目录及私有构建报告，默认不索引 |
| `npm run build:static -- --production --site-url URL` | 采用确认后的正式URL生成生产包；不执行上传 |
| `npm run check:release -- --site DIR` | 校验公开字段、路由、排除待审及私密文件 |
| `npm test` | 数据归一化、领域边界、发布门禁和必要回归测试 |

采集采用超时、有限重试、限流退避和来源独立错误记录。先读历史再增量更新；写入先验证，再原子替换并保留备份。重复采集不复制 DOI，不清空历史，不覆盖人工字段。Crossref 以 ISSN 限定、合理时间窗和分页查询；登记更新水位与发表日期分开，回溯重叠用于补迟到元数据。超出处理上限时显示截断与补采计划。

## 阶段 4：做出可用的前台和审核入口

基础站至少具备：论文卡片、详情原文/DOI、期刊与主题筛选、搜索、日期依据、空状态、待审不公开。然后按需求加入：

- 周报：按选定时区周一分组；DOI登记日期与日期未确认单列，不伪装为本周新发表；历史回顾不声称当时已采集。
- RSS：输出真实XML、绝对原文/详情URL和正确转义；没有新论文时仍是有效 feed。
- BibTeX/RIS：保留原始作者和题名，转义特殊字符，实际下载核查编码。
- 收藏/已读/稍后读：浏览器 localStorage，说明同源限制与导出备份；不是跨设备同步。导入整批校验、避免覆盖已有人工阅读状态。
- 精选：没有签发则显示零或隐藏；不拿普通相关性评分冒充推荐。
- 来源面板：分别显示最近尝试、最近成功、覆盖窗口、错误与零新增；不能以零新增证明没有漏报。

审核首先可用本地界面或命令行，保存理由、作者和时间。在线写入后台是单独增强：必须有真正服务端鉴权、版本冲突检查和审计，不能把密码、GitHub token 或写接口直接放在公开 JS。

## 阶段 5：先验收，再连接云端

用至少一个真实期刊、一篇真实相关论文和一个不相关反例走完采集→审核→构建→本地浏览器。扩大期刊列表时逐源保存核查结果。测试通过后继续 [GitHub与Pages操作](github-and-pages.md)，不要把只有模拟卡片的界面作为已完成的论文站。
