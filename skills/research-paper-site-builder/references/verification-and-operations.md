# 验收、监控与恢复

## 必要验收

按实际实现运行测试和浏览器验收，保存时间、命令、版本与观察结果。下表是行为条件，不能用“文件存在”替代。

| 范围 | 可观察的通过条件 |
|---|---|
| 配置 | 正常配置通过，空领域、重复ID、无效参数、伪verified来源被拒绝；draft与ready区分 |
| 来源 | 每刊真实请求、响应类型与一条原文身份核对；未通过的刊明确pending/disabled |
| 范围 | 正例入候选、领域外反例被标记、歧义进待核；主题词不单独放行 |
| DOI | URL前缀/大小写/尾标点归一后去重；重复运行不增重复，不丢旧条目 |
| 时间 | online、卷期、登记、年/月精度和未来日期有区别；跨时区周报分组正确 |
| 人工优先 | 已include→后续来源失败进入待补证；不会重复要求人工include；hold/exclude不被自动覆盖 |
| 导读 | T/A/F标签真实；引文必须属于对应原始证据；无摘要不编结果，坏模型JSON不放行 |
| 构建 | 待审单篇被排除，技术错误触发配置的阻断；公开字段白名单无摘要/私有理由/凭据 |
| 前台 | 搜索筛选、空状态、真实详情、周报、RSS、引用下载和移动宽度实际可用 |
| 持久化 | 云端第二次运行能读上次结果；候选分支非强推写入，远端变化拒绝覆盖 |
| 发布 | 固定main/candidate SHA、public内容摘要和上传包一致；内容未变跳过上传 |
| 线上 | HTTPS、首页、论文深层链接、周报、RSS有效XML、sitemap、未知路由404、manifest摘要正确 |

没有访问控制的公开站，在线后台写接口必须不存在或拒绝未授权请求。有后台时额外验证：未登录/非允许用户拒绝、跨站提交拒绝、过期候选版本拒绝、已提交/已保存/已上线分别反馈、登录在真实云端运行时成立。只测模拟OAuth或假码路径不能证明真人登录成功。

公开版本建议 `release-manifest.json` 保存：schemaVersion、trustedCodeSha、candidateDataSha、configDigest、publicDigest、builtAt、paperCount。摘要覆盖实际公开内容并排除自引用摘要字段与纯构建时刻；只凭篇数相同不能证明版本一致。私有构建report记录排除原因与门槛，不放公开目录。

静态包检查包含内容检查而非只查文件名：任意被重命名的JSON也不能泄漏内部字段；所有URL在正式origin/basePath下，预览noindex不会遗留到有索引需求的正式站；未知详情路由不能返回看似成功的空壳。

## 常见失败的定位顺序

| 现象 | 先查证据 | 处理 |
|---|---|---|
| 本地可采，Actions失败 | 相同入口的HTTP状态、Content-Type、区域访问、限流 | 使用已核查替代源/退避；保留失败，不隐藏 |
| 每次采集都“新增” | DOI规范化与旧状态恢复路径 | 修复幂等与持久化，保留旧记录 |
| 新论文不见了 | 范围、类型、日期、导读、来源健康、审核指纹 | 说明在哪层阻塞，不能直接改public绕门禁 |
| 修改期刊却仍收旧领域 | 所有关键词、模型门槛、提示词、前端主题、全收特例 | 统一配置并加跨领域反例 |
| 工作流成功但没上线 | deploy开关、AUTO_PUBLISH、无变化跳过、真实部署步骤 | 查manifest和部署ID，不只看绿色勾 |
| 上传成功但验收失败 | 线上版本、路由、缓存、实际项目/域名 | 线上可能已变更，记录后按授权回退 |
| 云端token过期 | 认证分类、有效期、安全刷新机制 | 停止该审核/发布能力，其余候选可继续保存 |
| 收藏丢失 | 协议/域名/端口是否变了、本地存储权限 | 解释同源边界，导出导入，不承诺云同步 |

## 稳定运行与成本

首次人工触发、首次自然定时触发、连续观察是三种证据。用约两周或适合期刊周期的观察窗口核对：来源成功率、官网新条目漏收/延迟、审核积压、模型费用、Actions分钟与artifact存储、重复发布。新刊可先小规模试采；不得把一次全成功写成稳定无漏收。

Actions artifacts会过期；关键审计与人工决定保存到私有Git或其他经用户选择的持久存储。不要承诺Actions/域名/模型永久免费或无限额度；按当前套餐与实测用量记录，关注预算而不是强制购买服务。大陆/目标读者网络可达性由对应网络实测，域名购买不会自动修复线路。

## 暂停与恢复

1. 关闭自动发布开关，保留线上正常版本；需要时单独暂停采集或审核，不混淆。
2. 记录故障run、main/candidate SHA、正常deployment ID、manifest摘要和可恢复包。
3. 数据冲突先保留候选与证据，人工核对，不强推、不清空数据。
4. 回退Pages到确认的正常deployment，或重新部署已核验旧包；都属于线上变更，按当前授权执行。代码回退并不自动等于数据与线上回退。
5. 恢复后重跑门槛与线上验收。若只是完成本地修复，明确写“待云端验证”。

交接跨电脑/会话时遵从项目约定写HANDOFF.md，记录下一步、路径、命令、状态、权限边界；不将密钥放入交接文件。
