# 从安装 Skill 到自己的论文网站

## 1. 你先准备什么

准备两项即可开始：期刊名称列表、研究关键词。可附官网和 ISSN，但不必自己先搜齐所有入口。再准备一个独立工作目录，供 Codex 生成网站项目；不要直接把分享仓库变成自己的论文数据库。

例子：

```text
期刊：Nature Communications；Science Advances。
方向：固态电池；锂金属界面；离子传输。
偏好：中文界面、英文原题；先人工确认收录。
```

下载 [分享包](../dist/research-paper-site-builder-2026-11-08.zip?raw=true)，把完整文件夹安装到 `~/.codex/skills/` 或对应 CODEX_HOME 目录。打开自己的网站工作区并调用 `$research-paper-site-builder`。

## 2. 先让代理完成本地闭环

代理负责：形成配置、核查期刊入口、实际抓取样例、实现去重与领域筛选、人工审核入口、前台与独立公开包。

你主要检查：

- 关键词扩展是否符合研究范围；多个兴趣被当作并集还是交集。
- 期刊是否是你要的那一本；来源有没有被误称为已接通。
- 导读是否标明依据；只看题名不能写出论文结果。
- 页面是否在你的电脑上实际打开；真实论文、筛选、详情与下载是否可用。

模型登录不是本地建站前提。没有模型时先人工审核，待审论文保留在队列中。

详细施工要求见 [端到端步骤](../skills/research-paper-site-builder/references/build-playbook.md)。其中 npm 命令是新网站项目应实现的接口；本分享仓库自带的是配置校验器。

## 3. 用你自己的 GitHub 存代码与数据

本地验收后，让代理准备文件清单、忽略规则与提交差异。你登录自己的 GitHub，指定仓库名和可见性，并在当前环境要求时授权创建和推送。

推荐私有仓库保存站点源码、候选和审核记录，公开网站只上传经过投影的文件。main 保存可信代码和人工决定；候选分支持久化自动采集结果。定时任务的临时磁盘不能代替候选分支。

先手动执行云端采集两轮，确认第二轮能恢复上一轮状态且 DOI 不重复，再启用 schedule。源码更改可通过分支/PR审阅；候选数据不能整分支盲目覆盖 main。

具体操作与命令见 [GitHub 操作手册](../skills/research-paper-site-builder/references/github-and-pages.md)。

## 4. 用 Cloudflare Pages 首次发布

你使用自己的 Cloudflare 账号创建或选择 Pages 项目。主路线是 Direct Upload：代理在本地/Actions构建，Pages接收公开输出。

先确定公开访问还是仅本人/团队访问。私有源码仓库不等于私有网站；需要私有访问时，HTML、JSON、RSS和下载都须受保护。

先构建独立生产包并检查内容，再上传其公开目录。按实际分配的正式 URL 核对 canonical、RSS、sitemap。上传后代理应核验 manifest 内容摘要、首页、论文深层链接、周报、RSS和404；你用目标网络确认访问与移动端体验。

生产凭据通过官方登录或 GitHub Secrets 提供；不要在聊天里发送 token。不要上传仓库根目录或整个 work 文件夹。

## 5. 最后再自动化

按此顺序扩大自动化：

1. 手动采集、审核、构建均通过。
2. 手动线上部署和线上版本核验通过。
3. 云端两轮持久化通过。
4. 启用每日采集，等待首次自然定时触发，区分它与手动触发。
5. 如需模型审核，单独接入安全授权、预算与证据校验。
6. 如需自动发布，明确条件并开启开关；内容未变跳过上传，故障保留可恢复版本。

日常看来源健康、审核积压、官网漏收/延迟与费用。论文未上线时先查它卡在范围、证据、审核、构建还是上传，不直接改公开 JSON 绕过校验。详见 [验收与运维](../skills/research-paper-site-builder/references/verification-and-operations.md)。

## 可直接使用的后续提示词

```text
本地网站已经验收，请检查当前文件与远端状态，准备我的 GitHub 私有仓库和 Cloudflare Pages 首次部署。先给出将上传的具体文件清单、公开构建包和验证结果；已有授权内连续完成，不重复询问。
```

```text
首次上线已验收，请先验证两轮云端采集能持续保存数据且不重复，再准备每日采集与自动发布配置。保留人工决定、待审队列、来源失败状态和上一正常部署。
```
